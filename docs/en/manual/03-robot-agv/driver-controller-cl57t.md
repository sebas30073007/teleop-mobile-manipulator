# Driver Controller (CL57T)

Custom-designed board based on **ESP32-C3** that generates the step signals for the manipulator's three motor drivers. Each driver is a **CL57T** (closed-loop, NEMA17-compatible).

![CL57T Controller — assembled board]({{ "/assets/img/Controlador.png" | relative_url }})

[⬇ KiCad Project — Manufacturing Gerbers (ZIP)]({{ "/assets/downloads/drivers_controller_gerbers.zip" | relative_url }}){: .btn .btn-outline }

## Requirements

- Independently control the manipulator's 3 axes (joints + shoulder)
- Generate **PUL / DIR / ENABLE** signals to each CL57T driver
- Support limit switches for calibration and homing routines
- Receive position commands from the NUC via I2C (through the H-Bridge master)

## Design

### CL57T Drivers

The CL57T is a closed-loop stepper (servo-stepper) driver that accepts digital pulse and direction signals. It operates in closed-loop mode using the motor's encoder to correct step loss.

| Parameter | Value |
|---|---|
| Compatible motor | NEMA17 |
| Loop type | Closed (incremental encoder) |
| Control signals | PUL, DIR, ENABLE (5V logic) |
| Max. current | Configurable via DIP on the driver |

### Controller board

The board generates the signals for the three CL57T drivers and manages the digital inputs from the limit switches:

| Function | Description |
|---|---|
| PUL/DIR/ENABLE outputs | One triad per axis (×3) |
| Digital inputs | Limit switches for calibration |
| Physical button | Locally triggerable homing routine |
| Communication | I2C slave — receives commands from the H-Bridge master |

## Implementation

Position commands travel from the NUC through the H-Bridge master's serial port (USB → COM4), and the master forwards them to this board over the I²C bus. The board executes step interpolation locally, without the NUC having to manage real-time signals.

### Axis command flow

```
Meta Quest (XR)
    │ ZMQ cmd (manip_cmd)
    ▼
NUC (Python 3.12)
    │ Serial COM4
    ▼
H-Bridge master (ESP32-C3)
    │ I²C addr 0x0B (ASCII text)
    ▼
CL57T Controller (ESP32-C3)
    │ PUL / DIR / ENABLE
    ▼
CL57T Driver × 3
    │
    ▼
NEMA17 + planetary gearbox × 3 (manipulator joints)
```

### ASCII protocol over I²C (slave `0x0B`)

The master writes ASCII text terminated with `\n` to the I²C buffer; the controller places the response in the 96-byte read buffer. All commands block until the movement finishes (synchronous).

| Command | Argument | Response | Description |
|---|---|---|---|
| `PING` | — | `PONG` | Verify the slave responds |
| `STATE?` | — | `OK busy=0 sw2=0 sw3=0 calibrated=1 base=0.00 codo=45.00 muneca=-90.00` | Full status |
| `HOME_ALL` | — | `OK HOME_ALL` / `ERR HOME_ALL` | Homing of elbow + wrist |
| `HOME_CODO` | — | `OK HOME_CODO` | Elbow-only homing |
| `HOME_MUNECA` | — | `OK HOME_MUNECA` | Wrist-only homing |
| `BASE_GOTO` | `degrees` | `OK BASE 45.000` | Absolute base position |
| `BASE_REL` | `delta_degrees` | `OK BASE -10.000` | Relative base position |
| `CODO_GOTO` | `degrees` | `OK CODO 90.000` | Absolute elbow position |
| `CODO_REL` | `delta_degrees` | `OK CODO 5.000` | Relative elbow position |
| `MUNECA_GOTO` | `degrees` | `OK MUNECA -45.000` | Absolute wrist position |
| `MUNECA_REL` | `delta_degrees` | `OK MUNECA -10.000` | Relative wrist position |
| `POSE` | `base elbow wrist` | `OK POSE base codo muneca` | All 3 axes in sequence |

Parser core (simplified):

```python
def exec_command(cmdline):
    parts = cmdline.strip().split()
    cmd   = parts[0].upper()

    if cmd == "PING":        return "PONG"
    if cmd == "STATE?":      return "OK " + estado_actual_str()
    if cmd == "HOME_ALL":    return "OK HOME_ALL" if home_all() else "ERR HOME_ALL"
    if cmd == "BASE_GOTO":   ir_base_a_deg(float(parts[1]));   return "OK BASE ..."
    if cmd == "CODO_GOTO":   ir_codo_a_deg(float(parts[1]));   return "OK CODO ..."
    if cmd == "MUNECA_GOTO": ir_muneca_a_deg(float(parts[1])); return "OK MUNECA ..."
    if cmd == "POSE":
        ir_base_a_deg(float(parts[1]))    # base: no effect on wrist
        ir_codo_a_deg(float(parts[2]))    # elbow: drags wrist compensation
        ir_muneca_a_deg(float(parts[3]))  # wrist: adjusts on top of compensation
        return "OK POSE ..."
```

### Homing routine — 4-phase algorithm

Every time the robot is powered on, `HOME_ALL` must be run to establish the elbow and wrist zero position. The base has no limit switch and starts from wherever it is.

```
Phase 1 — Fast search:   moves toward the switch at 1,800 µs/step
                          until SW2/SW3 triggers
Phase 2 — Backoff:       retreats 220 steps at 3,200 µs/step
Phase 3 — Fine search:   moves forward again at 3,200 µs/step
                         (lower speed = higher repeatability precision)
Phase 4 — Final clearance: retreats 120 steps → reproducible zero position
```

```python
# Example: elbow homing (wrist follows the same pattern with SW3)
mover_codo_home(AWAY_SIGN_CODO, BACKOFF_STEPS, PULSE_HOME_SLOW_US)      # 220 steps back
ok, _ = buscar_switch("CODO", mover_codo_home, HOME_SIGN_CODO, SW2,
                       PULSE_HOME_SLOW_US, BACKOFF_STEPS + 300, 1)      # fine search
mover_codo_home(AWAY_SIGN_CODO, FINAL_CLEARANCE_STEPS, PULSE_HOME_SLOW_US)  # 120 steps
pos_codo = FINAL_CLEARANCE_STEPS                                         # logical zero
```

The physical button (GPIO0, long press) runs `HOME_ALL` without requiring the NUC — useful during development or error recovery.

### Limit switches

The limit switches define the reference (zero) points for each joint.

![Limit switch — upper joint — manipulator base]({{ "/assets/img/Finales de carrera.png" | relative_url }})

Switch reading applies a 5 ms debounce with double confirmation to avoid false triggers from mechanical vibration:

```python
def switch_active_confirmed(sw_pin, confirm_ms=5):
    if sw_pin.value() == 0:       # active low
        sleep_ms(confirm_ms)
        return sw_pin.value() == 0
    return False
```

### Wrist mechanical compensation

The HTD3M belt transmission between the elbow and the wrist mechanically couples both axes: when the elbow rotates, the wrist rotates with it even if no command was sent. The firmware corrects this by emitting compensation pulses to the wrist motor in parallel with the elbow's, keeping the logical angle (`pos_muneca`) stable:

```python
# Two independent variables for the wrist:
# pos_muneca       = logical angle (what the user sees and commands)
# pos_muneca_motor = accumulated physical motor position

# During mover_codo():
#   → pos_muneca_motor changes (COMP_RATIO compensation steps are emitted)
#   → pos_muneca does NOT change

# During MUNECA_GOTO:
#   → both variables change

COMPENSATE_MUNECA_WITH_CODO = True
COMP_RATIO = 1.0    # 1 elbow step → 1 wrist compensation step
```

### Speed ramps (trapezoidal profile)

The 3 axes use independent ramps to avoid step loss on startup and vibration on braking:

```python
# Identical configuration for BASE, ELBOW, and WRIST
*_RAMP_START_US  = 2500   # initial speed (long pulse = slow)
*_RAMP_CRUISE_US = 1600   # cruise speed
*_RAMP_END_US    = 2500   # braking speed
*_ACCEL_STEPS    = 1500   # steps in acceleration ramp
*_DECEL_STEPS    = 1500   # steps in deceleration ramp
```

Profile: linear acceleration → cruise → linear deceleration.

### State published to the NUC

The board reports status in response to `STATE?`:

| Field | Description |
|---|---|
| `busy` | `1` if any axis is moving |
| `sw2`, `sw3` | Current state of the limit switches |
| `calibrated` | `1` if at least one `HOME_ALL` has completed |
| `base`, `codo`, `muneca` | Current logical angles in degrees |
